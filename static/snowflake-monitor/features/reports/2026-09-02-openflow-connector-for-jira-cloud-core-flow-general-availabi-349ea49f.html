Openflow Connector for Jira Cloud: Core flow (General availability)

2026-09-02機能アップデートGeneral availability

Jira Cloudの課題・プロジェクト・ユーザーなどを、明示的なスキーマのSnowflakeテーブルへ継続的に取り込めるようになります。

Atlassian Jira Cloud (Core) flowは、Jira Cloudの課題、プロジェクト、ユーザーおよび関連データをSnowflakeへ取り込むOpenflow Connectorです。取り込み先には明示的なスキーマを持つ専用テーブルが使用されます。削除追跡をオプションで有効化でき、プロジェクト間の並列取り込みにも対応します。Jira Cloud (Agile) flowは引き続きPublic Previewです。

01

なぜ重要か

Jira Cloudの業務データをSnowflakeで分析する際、課題や関連エンティティを取り込む連携処理の整備が必要でした。本機能では、Core flowがGeneral availabilityとなり、専用テーブルへの取り込み、削除追跡、プロジェクト単位の並列取り込みを利用できます。

02

対象となるチーム

  • Snowflakeデータ基盤・データ統合チーム
  • Jira Cloudを利用する開発・プロジェクト管理チーム
  • 開発生産性・プロジェクト分析の担当者
  • BI・データ分析チーム
03

提供条件

  • 提供ステータス: General availability
  • 対象: Atlassian Jira Cloud (Core) flow
  • エディション: リリースノートに記載なし
  • リージョン: リリースノートに記載なし
  • 削除追跡はオプション、プロジェクト間の並列取り込みに対応
04

ユースケース

  • Jira Cloudの課題データをSnowflakeに集約し、プロジェクト別の進捗、件数、担当状況を分析する。
  • プロジェクト、ユーザー、関連データを組み合わせ、チームや担当者単位の開発状況を可視化する。
  • 削除追跡を利用し、Jira Cloud側で削除されたデータを考慮した履歴管理やデータ品質確認を行う。
  • 複数プロジェクトのデータを並列に取り込み、対象プロジェクトが多い環境での連携処理に利用する。
05

仕組みと使い方

OpenflowでAtlassian Jira Cloud (Core) flowを構成し、Jira CloudのデータをSnowflake上の専用テーブルへ取り込みます。必要に応じて削除追跡を有効化し、複数プロジェクトを対象に並列取り込みを利用します。具体的な接続設定、認証、テーブル定義、実行方法は、公式ドキュメント「About Openflow Connector for Jira Cloud」で確認してください。リリースノートにはSQLやコマンド例の記載はありません。

06

導入ステップ

  1. 公式の「About Openflow Connector for Jira Cloud」を読み、Core flowの前提条件と構成方法を確認する。
  2. Jira Cloud側の接続対象、プロジェクト、利用するデータ範囲を整理する。
  3. Snowflake側でOpenflow Connector for Jira Cloudの利用可否、権限、配置先を確認する。
  4. 検証用の小規模な対象範囲でCore flowを構成し、専用テーブルへの取り込みを実行する。
  5. 削除追跡とプロジェクト間の並列取り込みを必要性・性能の観点で個別に検証する。
  6. 取り込み結果、スキーマ、更新・削除時の挙動を確認して本番適用を判断する。
07

運用上の注意

  • 削除追跡はオプション機能のため、削除データを分析や監査で扱う必要があるかを先に決めてください。
  • 並列取り込みを利用する場合は、対象プロジェクト数や取り込み結果を検証し、環境に適した構成か確認してください。
  • 専用テーブルの明示的なスキーマを前提に、既存の分析処理やデータモデルとの対応関係を確認してください。
  • 認証方式、必要権限、同期頻度、再実行時の挙動はリリースノートに記載されていないため、公式ドキュメントで確認が必要です。
08

制約事項

  • Jira Cloud (Agile) flowはGeneral availabilityではなく、引き続きPublic Previewです。
  • リリースノートでは、対応するJira Cloudの詳細エンティティ、同期頻度、性能上限は明記されていません。
  • エディション、リージョン、必要なSnowflake権限、Jira Cloud側の前提条件はリリースノートに記載なしです。
09

次に確認すること

  • 公式の「About Openflow Connector for Jira Cloud」で、Core flowの接続設定、認証、権限、対応データを確認する。
  • 利用中のSnowflakeアカウントで、対象リージョンとエディションにおける提供状況を確認する。
  • 検証環境で専用テーブルのスキーマ、削除追跡、複数プロジェクトの並列取り込みをテストする。
  • Agileデータが必要な場合は、Public Previewとしての利用条件と本番利用可否を別途確認する。
